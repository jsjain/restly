# Themes

VS Code themes, color tokens, and the contrast guard. Part of the [Restly spec](README.md).

## D20 Themes

Themes are VS Code color themes. `theme/vscode.ts` converts a theme's `colors` and `tokenColors` (JSON with comments) into Restly's CSS custom properties, filling missing keys from VS Code's defaults for that theme type, so a custom theme is written with VS Code's documented color keys. A `restly.<token>` key under `colors` sets any Restly color token directly, including ones VS Code has no key for (method badges, variable highlights, the dialog backdrop), and unknown `restly.*` keys produce a warning. No stylesheet or component holds a literal color, which `frontend/checks/colors.check.ts` enforces, and the native window background follows the active theme's surface after the first frame. Dark follows VS Code Dark Modern with every background and border 7 steps lighter, so its surface is #262626 (the user's choice on 2026-09-15), Light follows Light Modern, and One Dark follows OneDark-Pro, all produced by the same converter. Imported files are kept unchanged in the per-machine `themes/` folder and converted at startup. The active imported theme's converted values are cached so it applies before the first render. A contrast guard moves only failing foregrounds by the smallest step: text at least 4.5:1 on the surfaces it sits on, the focus ring at least 3:1, and selected text at least 4.5:1 on the selection color (3:1 for variable colors). Input and dropdown outlines only have to be visible (1.4:1), as in VS Code and Postman, because fields are recognized by their fill and placeholder. On 2026-09-14 the user rejected 3:1 outlines as heavy boxes next to Postman. Checkboxes, which have no fill or text to identify them, are outlined in `textSubtlest`. The code editor highlights the cursor line the way VS Code does, with `lineHighlight` and `lineHighlightBorder` (`editor.lineHighlightBackground` and `editor.lineHighlightBorder`): in every editor, including the read-only response viewer, which stays focusable so it shows a cursor and Find works in it, and only while nothing is selected, because CodeMirror draws the selection under the lines and a fill would hide it. The gutter has no border and the active line number is marked by color, as in VS Code (the user asked for a VS Code-like editor on 2026-09-15). Layout dividers keep the theme's own colors: the first of `sideBar.border`, `editorGroup.border`, `panel.border`, and `tab.border` that is lighter than the background on a dark theme (darker on a light one), because a line on the other side reads as a gap. On 2026-09-15 the user rejected One Dark Pro's `#181a1f` group border for that reason, and its `#3e4452` panel border is the line VS Code shows. The guard then holds `border` and `borderSubtle` to 1.4:1 on the surface and the sidebar. Dark Modern's own `#2b2b2b` divider on `#1f1f1f` is 1.17:1, and the user reported the table grid as invisible in Dark more than once. Postman's grid is about 1.33:1 (2026-09-15). Scrollbar thumbs use `scrollbarSlider.background` and `scrollbarSlider.hoverBackground` and appear only while the pointer is over the scroll area. `frontend/checks/theme-contrast.check.ts` checks every built-in and imported theme. `include` in a theme file is not followed and shows a warning. The UI font defaults to Inter, bundled through `@fontsource-variable/inter`, and the UI and editor fonts and sizes can be changed in Settings.
