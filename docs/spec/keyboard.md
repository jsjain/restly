# Keyboard

Commands, shortcuts, keybindings.json, and find. Part of the [Restly spec](README.md).

## D23 Keyboard

One command registry drives the shortcuts, a command palette with fuzzy search over commands, requests, environments, and history, and a shortcuts help overlay. Tabs close on middle click and have a context menu. `keybindings.json` in the per-machine data folder overrides default keys in VS Code's format, reloaded on window focus, without `when` clauses or two-step chords. The default keys are `frontend/src/keybindings.default.json`, in that same format, and `registerCommand` reads a command's keys from it by id, so the file users read in the repository is the one the app runs. Cmd/Ctrl+F (`find`) opens a find widget modeled on VS Code's (`frontend/src/editor/SearchPanel.tsx`, CodeMirror's `createPanel` hook): it floats at the top right over the text, has match case, whole word, and regular expression toggles inside the field, a "3 of 12" count (counting stops at 1000, and "?" means the cursor is not on a match), previous and next, and a replace row behind a chevron that read-only editors do not show. Enter goes to the next match, Shift+Enter to the previous, Escape closes. Find in selection is not offered. It opens in the focused editor, else in the editor of the pane last clicked (request or response), else in the response body. The collection tree is a keyboard-navigable tree with a roving tab stop. Unmatched keys outside text fields have their default prevented, because WKWebView passes unhandled keys to the native window, which plays the system beep; editing and system chords, and any chord typed into a text field, pass through.
