1
Results are filtered and grouped, and the match is highlighted.

Each result shows its method, its name with the matched letters in the accent color, and the collection path as a quiet subtitle. The query field uses the UI font, where the current placeholder is monospace. The current palette lists every command whatever you type.

2
Every row has an icon, a name, a group subtitle and a right-aligned shortcut.

The group name now sits right after the title instead of floating in a misaligned middle column, and the keycap is flush right. Rows in the current palette have no icons, so commands, requests and history are harder to tell apart. Environments appear as their own group when the query matches one.

3
A footer lists the keys that work inside the palette.

Navigate, open, close and commands-only are already supported. "Open in new tab" with ⌘↵ is a proposed addition. The current palette has no hints, so the ">" prefix is only discoverable from the placeholder.

4
Opened with ⌘P, the palette shows a "Requests" chip (proposed).

The chip says the search is limited to requests, so Commands, Environments and Recent are not mixed in. ⌘K keeps the full mixed list shown above.

5
The filter and the keybindings.json button share one row.

Both are the same controls as today, but the button is a quiet ghost button next to the filter instead of a separate full-weight button. The overlay is 640 px wide so two columns of groups fit.

6
Two columns, one line per shortcut, keycaps right-aligned.

Groups are Request, Navigation, Tabs and View, with a hairline under each heading. Each key is its own keycap. The faint command id on every row is gone, because it is noise for anyone who is not editing keybindings.json.

7
A "custom" tag marks a customized binding.

It replaces the "*" suffix, which looked like a footnote with no footnote. The tag sits next to the keycaps, so it reads as a property of the binding.
