The request bar matches HTTP requests, with live state beside it.

The static WS badge moves inside the URL field in place of the method menu. The status becomes a colored dot with a connection timer (the timer is proposed), and Connect or Disconnect sits right next to it. Today these are loose items in a plain toolbar, and Save moves up to the breadcrumb row like every other request.

2
Params, Headers and Auth stay, in a short area.

The three sub-tabs keep their content, but the editor is capped at about 90 px so the message log gets most of the height.

3
One toolbar for the log.

The filter field gets a search icon, the message count sits beside it and Clear log is a ghost button. Today these sit under the message box, so the log is the last thing on the screen.

4
Log rows use icons and a quiet timestamp.

Sent is a muted up arrow, received is a blue down arrow, system events are a small dot and errors are a red alert icon. Bodies are monospace and cut off with an ellipsis. The text glyphs of the current log become icons, and each message is one line.

5
An open message shows pretty-printed JSON with a Copy icon (proposed).

The expanded block uses the same code view as responses, with line numbers. The Copy button is new. Today the row expands on click and shows the formatted body.

6
The open event says it expands (proposed label).

"Handshake headers" with a chevron makes the hidden content visible. Today clicking the Connected row reveals the headers. The label tells you before you click.

7
The composer is pinned to the bottom, with ⌘↵ and a JSON tag (proposed).

A multi-line monospace box and one primary Send button. The shortcut and the tag are proposed. There is no text or binary toggle, because the app sends the text as typed.

8
Disconnected is clear at a glance.

The status reads in red with the close code and reason, Connect becomes the primary button, and the composer and Send are dimmed. Today the status is plain text, and only Send is disabled.
